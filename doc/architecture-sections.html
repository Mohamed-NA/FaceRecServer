FaceRecServer

Architecture breakdown — five sections covering system overview, recognition flow, enrollment flow, Docker deployment, and component dependencies.

Mohamed Nasser · FaceRecServer v0.1.0
Section 01

System Overview

The browser captures camera frames and sends them over a WebSocket to the Flask server. The server runs face recognition on each frame, annotates it with coloured bounding boxes, and streams the result back alongside a structured list of detections. All known-face embeddings are stored in a single JSON file on disk.

Browser Captures camera frames via getUserMedia, displays the annotated stream on a canvas, and hosts the enrollment UI.
Server Flask + SocketIO server that decodes each frame, runs recognition, draws boxes, and re-encodes the result as JPEG.
Storage A plain JSON file maps each person's name to a list of 128-d face vectors. No database required.
WebSocket Four events carry all data: video_frame →, ← server_frame, ← detections, enroll_request →.
Section 02

Recognition Flow (per frame)

Every frame sent by the browser triggers this pipeline. The server locates all faces, computes their 128-d embeddings, and compares each one against every stored vector using Euclidean distance. Faces below the threshold (0.5) are labelled with their name; faces above it are numbered Unknown 1, 2, 3 … sorted left-to-right.

HOG Detection face_locations() uses a Histogram of Oriented Gradients model to find bounding boxes. Fast enough for real-time use on CPU.
128-d Embeddings face_encodings() runs a dlib ResNet (trained on 3 M faces, 99.38% LFW accuracy) to produce a compact numeric fingerprint per face.
Distance Threshold Euclidean distance below 0.5 = same person. Above 0.5 = unknown. Configurable in config/recognizer.json.
Left→Right Sort Unknowns are numbered by their left-edge x-coordinate, giving stable labels across frames regardless of detection order.
Section 03

Enrollment Flow

When the server sees a new person it cannot identify, it labels them Unknown N. The user can click that face on the canvas to highlight it, then open the Add Person panel, type a name, and click Save All. The server extracts the embedding from the stored frame at that exact bounding box and appends it to the JSON database. The person is recognised on the very next frame.

Zero Training Time Enrollment takes under 5 seconds. No offline data collection, no model retraining — just point and name.
Multi-Person Batch All unknowns can be named in one "Save All" click. The client fires one enroll_request per filled row in parallel.
Persistent Storage Vectors are appended to face_embeddings.json immediately. They survive server restarts and are used on the very next frame.
Multiple Samples Enrolling the same person multiple times (different angles) appends more vectors. All are compared independently, improving accuracy.
Section 04

Docker Deployment

The stack uses two Docker images. A lightweight models container unpacks the face embeddings into a shared volume and exits immediately. The app container then starts, mounts the volume, and serves the recognition API. GitHub Actions builds and publishes both images automatically.

Two-Image Pattern Separating models from app keeps the app image lean and allows model updates without rebuilding the full Python/dlib environment.
Startup Order compose.yaml uses depends_on with condition: service_completed_successfully, guaranteeing embeddings exist before the app reads them.
Writable Volume The shared volume is mounted read-write so live enrollments made during a session persist inside the running container.
CI Triggers Tests run on every push. The app image is pushed on main/tags. The models image (large) is only rebuilt on version tags.
Section 05

Component Dependency Map

The codebase has four Python modules and two data files. app.py is the entry point and depends on inference.py. Both depend on paths.py for file-system constants. inference.py wires together face_recognition (dlib), OpenCV, and the embeddings JSON.

app.py Entry point. Owns the WebSocket event loop, the shared frame/results lock, and the SSL context. Delegates all recognition work to inference.py.
inference.py Self-contained FaceRecognizer class. No Flask dependency — can be imported standalone for testing or CLI use.
paths.py Walks up from __file__ until it finds pyproject.toml, resolving paths portably regardless of where the process is launched.
Data files Both JSON files (embeddings + config) live outside the Python package, keeping code and data cleanly separated and Docker-volume-friendly.
